## REQ-004 已完成（eb6a49b）
- 描述：压缩音频大小，降低数据传输成本
- 提出日期：2026-09-21
- 备注：实时录音在浏览器推流模式下优先使用 32 kbps 单声道 WebM/Opus（约 14.4 MB/小时），并请求 16 kHz 单声道采集以适配语音识别；设备不支持该封装时依次尝试 Ogg/Opus、MP4/AAC 或浏览器默认编码，兼容 Web、Android 与 iOS WebView。原生离线识别模式仅上传文字，不传输音频；用户选择的既有音视频文件保持原样上传，避免客户端实时转码带来的等待与兼容问题。录制界面显示实际累计传输量和编码码率。

## REQ-005 已完成（eb6a49b）
- 描述：录制状态旁增加实时流量监控
- 提出日期：2026-09-21
- 备注：实时录制状态旁显示累计音频净荷、实时音频净荷速率和编码码率（不将协议开销、下行数据及其他接口流量计入音频指标）；速率根据每个成功进入 WebSocket 发送队列的音频分片及实际时间间隔计算，并进行轻度平滑，每约 2 秒更新。暂停时速率归零，恢复后重新采样；原生离线识别模式明确显示音频净荷为 0 B/s，仅上传识别文字。
